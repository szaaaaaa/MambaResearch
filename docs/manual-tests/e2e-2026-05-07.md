**关键观察**：

1. **每个 run 都恰好出现 1 次 `replan` 事件**——结构化原因：planner 第一轮总是先调 `clarify_intent` 技能，但该技能不必产出 `ClarifiedIntent`（Run #2 例外，初轮 14 events 时已带回 4 events 的 `needs_replan` observation），导致 observation 触发 1 次硬重规划。这是当前流水线的"必然 1 次"，不代表错误。
2. **`planning_iteration` ≥ `replan` 事件数**：reviewer 触发的修订（如 Run #1: 6.4 → 6.6 经 review_round 2）会让 planner 再跑一次但**不**记 `replan` 事件，所以 plan_iter 比 events 计数大。这是两个不同口径。
3. **tool 调用次数 Run #3 异常低**（14 vs 50/53）：RAG 主题第 1 轮规划只产出 3 节点（少了 `fetch_fulltext`），且后续节点更多走 LLM-only 技能而非检索/抓取工具。说明 planner 会按主题特性降配，不是固定流水线。
4. **wall_time 集中在 13 ± 1 min**——主要时间花在 LLM 合成（draft_report / extract_notes），而非检索。

### Run #1 — Mamba vs Transformer

**Title**：*Are Mamba and State Space Models Really Better than Transformers for Long Sequence Modeling? A Survey of Evidence, Efficiency, Dependency Modeling, and Deployment Fit*

**Sections (9)**：Introduction · From Efficient Attention to Selective State Spaces · Evidence on Training Efficiency · Evidence on Inference Speed and Memory · Long-Range Dependency Modeling · Hybrid Architectures and the Emerging Middle Ground · Evidence Quality, Corpus Limitations, and Benchmark Needs · Scenario-Specific Recommendations · Conclusion

**Abstract**（1980 字符）：
> Mamba and modern state space models have rapidly emerged as prominent alternatives to Transformers for long sequence modeling. Their appeal is intuitive: standard self-attention has quadratic dependence on sequence length, whereas structured and selective state space models are designed around linear-time sequence processing and recurrent state updates. This survey examines whether the available evidence supports the stronger claim that Mamba and state space models are generally superior to Transformers on long sequences. Based on the provided artifacts, the answer is necessarily qualified. ... However, the artifacts also reveal substantial evidence gaps: they do not provide unified benchmark results, training-time comparisons, memory measurements, inference latency, throughput, or controlled evaluations of long-range dependency accuracy across matched Transformer and Mamba settings. The most defensible conclusion is therefore not that Mamba universally dominates Transformers, but that it is a strong candidate in regimes where long contexts, streaming inference, memory limits, continuous signals, graph sequences, audio, medical volumes, and spatiotemporal data make quadratic attention costly. ...

### Run #2 — PagedAttention

**Title**：*PagedAttention in vLLM: A Survey of KV Cache Fragmentation Control and High-Concurrency LLM Serving*

**Sections (10)**：Introduction · The KV Cache Fragmentation Problem · PagedAttention Design Principles · How Paging Reduces KV Cache Fragmentation · Comparison with Contiguous KV Cache Allocation · Throughput and Memory Benefits Under High Concurrency · PagedAttention in the Broader KV Cache Optimization Landscape · Design Tradeoffs and Practical Considerations · Synthesis · Conclusion

**Abstract**（2007 字符）：
> Autoregressive large language model serving is increasingly constrained by the key-value cache, whose memory footprint grows with the number of active requests, the sequence length, the number of layers, and the attention width. ... This survey analyzes how vLLM's PagedAttention addresses this systems problem by replacing per-request contiguous KV cache regions with fixed-size cache blocks, logical-to-physical block tables, free block pools, reference counting, and copy-on-write sharing. The central design principle is that each sequence remains logically contiguous while its KV cache is physically non-contiguous. ... Reported vLLM results show approximately 2--4× throughput improvement over systems such as FasterTransformer and Orca at comparable latency, although the exact gain depends on workload length distribution, model architecture, block size, scheduling policy, and concurrency level.

### Run #3 — RAG Factuality

**Title**：*Evaluating Factuality in Retrieval-Augmented Generation: Benchmarks, Automatic Metrics, Limitations, and Future Directions*

**Sections (11)**：Introduction · What Should Factuality Evaluation Measure in RAG? · RAGAS and Pipeline-Oriented Automatic Evaluation · TruthfulQA and General Truthfulness Benchmarks · FActScore and Claim-Level Factual Precision · Groundedness, Attribution, and Citation Support · Domain-Specific and Multilingual Evaluation Pressures · Automatic Judges, Uncertainty, and Evaluation Robustness · Failure Modes of Existing Benchmarks and Metrics · Toward Improved Evaluation Protocols · Conclusion

**Abstract**（1924 字符）：
> Retrieval-augmented generation has become a central architecture for grounding large language model outputs in external knowledge, yet its factual reliability remains difficult to evaluate. ... This survey analyzes how factuality in retrieval-augmented generation should be evaluated, with particular attention to RAGAS, TruthfulQA, FActScore, factual consistency benchmarks, attribution metrics, and hallucination detectors. We argue that factuality evaluation must separate answer correctness from groundedness, evidence sufficiency, citation accuracy, factual coverage, and abstention behavior. ... Recent work on Face4RAG, FELM, FactKB, ICAT, factual recall, LettuceDetect, MetaRAG, HalluSearch, and attribution-oriented evaluation broadens the landscape toward span-level localization, coverage, multilinguality, and evidence auditing. The survey concludes that no single benchmark or automatic metric is sufficient for factuality assessment in deployed RAG systems. A robust evaluation protocol should combine scenario-specific gold evidence, claim-level verification, retrieval diagnostics, citation validation, refusal tests, evidence perturbations, uncertainty assessment, and expert-calibrated automatic judges.

## 11. 结论

3/3 完成，每篇 ~37k-43k 字符 LaTeX（约 5-7 页 PDF，全英文学术体）、9-10 个 section、审阅平均 6.73/10 通过。系统在三类不同主题（综述对比 / 系统工程 / 评估方法）下都能产出结构合规、内容贴题的初稿。

**单 run 成本基线**：
- 时间：~13 ± 1 分钟
- LLM 调用：9-11 个 skill × 约 2-5 个 tool 调用 = 14-53 次 LLM round-trip（受主题影响）
- token：未知（待补 §7 follow-up）

**口径警告**：
- `replan_count` 当前在所有"正常 run"上都恒等于 1（clarify_intent 触发的结构性重规划），不能用作健康度指标——若想监控异常重规划，需要排除 `node_clarify_intent` 类型或改看 `planning_iteration - 1`。
- 样本量 N=3 不能下结论说性能稳定；至少要 N≥5 且换不同时段重测才能看出方差。
