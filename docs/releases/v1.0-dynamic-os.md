# v1.0 - Dynamic OS（自建 Agent 框架完整形态）

> **Commit**: `fb33550` · **日期**: 2026-04-06 · **Tag**: `v1.0-dynamic-os`
>
> 项目在此版本更名为 **MambaResearch**

## 版本定位

**从零自建的多角色 agent 框架**，彻底摆脱 LangGraph 依赖，所有调度/执行/策略逻辑自主实现。1 句话研究主题 → 自动检索 30+ 篇文献 → 构建证据图谱 → 设计并真实执行实验（3 轮迭代）→ 生成带图表、引用、LaTeX 的研究报告。

这是"自建 agent 框架"路线的**完整形态终点**——之后的 v2.0 重构会把"大脑"切换为 Claude Code，本层退化为"科研基础设施层"。

## 主要能力

### 端到端实验闭环
- `run_experiment` 真实执行代码（非 prompt 模拟）：subprocess 沙箱 + workspace 隔离 + results.json 契约
- 3 轮实验迭代 + 早停 + 策略切换（refine / pivot）+ 最佳快照回滚
- 通用注册表模板让 LLM 可为任意课题生成实验代码

### LLM 驱动的动态 DAG 规划
- Planner 根据当前研究进度**实时生成**执行 DAG，不是固定流水线
- "是否做实验"、"何时终止"、"指标方向"全部由 LLM 语义判断，硬编码只做安全护栏
- 四项决策交给 LLM：role 路由、skill 选择、run termination、needs_review

### 7 角色协作
`conductor → researcher → experimenter → analyst → writer → reviewer → hitl`，每个角色可独立配置 LLM 模型。

### 多维审稿循环
5 维度评分（新颖性、可靠性、清晰度、重要性、完整性），不通过则自动修订重写，直到达标或达修订上限。

### 19 个内置 skill
`plan_research` · `search_papers` · `fetch_fulltext` · `extract_notes` · `clarify_intent`（多轮 HITL 澄清）· `build_evidence_map` · `design_experiment` · `run_experiment` · `analyze_metrics` · `analyze_trends` · `compare_methods` · `aggregate_results` · `generate_figures`（11 种图类型）· `draft_report`（完整 LaTeX + bilingual）· `review_artifact` · `reflect_on_failure` · `create_skill` · `optimize_skill` · `optimize_experiment`

### 类型化 artifact 契约
`ArtifactRecord` + `schema_version` + `source_inputs` 追溯链，18 种 artifact 类型（SearchPlan、SourceSet、PaperNotes、EvidenceMap、ExperimentPlan、ExperimentResults、FigureSet、ResearchReport、ReviewVerdict ...）。

### 完整基础设施
- Policy engine：权限边界 + 预算（max_tokens / wall_time / tool calls）
- MCP tool gateway：LLM / search / retrieval / exec 四类下游 MCP
- HITL：多轮 clarify_intent + ClarificationModal + stop button 跨刷新
- 前端：DAG 可视化 + run history + artifact 浏览器

## 技术栈

- **后端**：Python 3.10+ / FastAPI / 自建 runtime（非 LangGraph / 非 LangChain）
- **前端**：React 19
- **执行层**：Claude Code subprocess（作为 `run_experiment` 的代码执行后端，不作大脑）
- **文献搜索**：paper_search MCP（6 源：arXiv / Semantic Scholar / OpenAlex / PubMed 等）

## 当时的局限（也是 v2.0 的动因）

- **DAG 执行器定位过窄**：一次性跑完 `plan → ... → report` 然后结束，不支持"基于上次结果再迭代"、"中途介入重跑某一步"
- **无跨 run 研究资产沉淀**：论文、实验结果、笔记随 run 结束而"丢失"——每次都像从头来过
- **自建 Planner 在重造小 Claude**：LLM 决策权的四项 refactor 把 Planner 变成了 Claude 的简化版
- **技能扩展是假的**：`create_skill` / `optimize_skill` 是 stub
- **citation 非自动化**：`draft_report` 的 cite key 靠 config 硬编码，没有真正的 bib 系统

## 为什么进化到 v2.0

Claude Code 接入后意识到：**自建 agent 框架里的 planner / executor / DAG 调度层和 Claude Code 原生能力高度重叠**。v2.0 的重定位——Claude Code 作为大脑（planning / execution / HITL），本层保留**最有价值的部分**作为科研基础设施：
1. 类型化 artifact store（科研资产跨 session 持久）
2. 19 个 skill 的领域知识内核（以 MCP 工具形态对外）
3. 预算 monitor（Claude Code 原生不管）
4. 前端 artifact 可视化组件

> **这不是推倒重来**——是把 v1.0 的"骨架"砍掉，"内脏"和"皮肤"留下，换一颗更强的大脑。v1.0 的 contracts / skills / policy.budget / 前端渲染组件会继续存在于 v2.0 中。
