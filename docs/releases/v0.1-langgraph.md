# v0.1 - LangGraph 自主研究 Agent

> **Commit**: `2ddfe71` · **日期**: 2026-02-20 · **Tag**: `v0.1-langgraph`

## 版本定位

基于 **LangGraph** 状态图的首版自主研究 agent，从主题到带引用的研究报告走通一条端到端流水线。Phase 5-8 架构重构完成后的稳定形态——LangGraph 作为调度主角的最后一版，此后角色/多 agent 包装层开始加入。

## 主要能力

- **双模式运行**：Autonomous Agent 模式（`plan → fetch → index → analyze → synthesize → report`）+ 传统 RAG 模式
- **多源检索**：arXiv、Semantic Scholar、OpenAlex、Bing、CSE、GitHub providers
- **可插拔 provider 架构**：core / plugins / infra 三层分离，retrieval / LLM / search 各有插件注册表
- **LaTeX & 多模态 ingest**：PDF/LaTeX 解析、figure extraction、VLM captions
- **基础设施**：预算守卫、checkpoint、tracing、reviewer 质量门
- **实验规划雏形**：可选的 experiment-planning stage 针对 ML/DL 主题

## 技术栈

- **编排框架**：LangGraph（状态图节点调度）
- **索引**：Chroma 向量库 + 可选 reranking + BM25 sidecar
- **LLM**：OpenAI / Gemini 双后端
- **执行入口**：`scripts/run_agent.py`

## 当时的局限

- 节点之间是状态字典传递，没有类型化的 artifact 契约
- 调度是固定图结构，LLM 不参与"下一步做什么"的决策
- 无角色分工概念，所有节点共用同一套上下文
- 实验规划停留在 suggestion 层，不能真实执行代码

## 为什么进化到下一版

固定流水线满足不了真实科研的非线性。下一代 **v0.5 Research OS** 引入 3 角色分工（conductor / researcher / writer），首次把"谁做什么"显式化——不过底层依然跑在 LangGraph 上。
