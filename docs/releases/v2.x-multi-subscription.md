# v2.x Multi-Subscription Strategy: Claude 订阅 + ChatGPT 订阅并用

**Status**: 方案 F 已落地，方案 A 存档备用 — 后续 v3.0 已删除自建 dynamic_os runtime，参见 [v3.0 release](v3.0-mamba-as-claude-code-shell.md)
**Date**: 2026-04-24
**Scope**: 单个开发者同时使用 Claude Pro/Max 订阅与 ChatGPT Plus/Pro 订阅，共享项目 `.claude/` 配置资产，不依赖 API key 付费。

---

## 背景：为什么问题存在

ziang 同时持有 Claude Pro/Max 订阅和 ChatGPT Plus/Pro 订阅。目标：**两家订阅都能用于真实编码工作流，不退化成 API key 付费**。

此需求在 2026-04 的现实约束下，比想象中复杂。以下关键事实决定了可行方案的边界：

### 关键事实（2026-04-24 调研）

1. **Claude 订阅只能走官方 `claude` CLI**
   - 2026-01-09 起，Anthropic 封锁第三方工具消费 Claude 订阅 OAuth token
   - token scope 被限定为 `"only authorized for use with Claude Code"`，服务端基于请求指纹（User-Agent / `x-stainless-*` header / client_id）识别客户端身份
   - OpenClaw、OpenCode 等第三方工具的订阅通路在此事件后全部失效
   - 2026-04-04 Anthropic 官方完成订阅通路对第三方工具的全面切断

2. **ChatGPT 订阅 Codex OAuth 官方允许第三方**
   - PKCE flow against `auth.openai.com`
   - OpenAI 明确支持第三方 CLI（OpenCode、OpenClaw 等）通过此 OAuth 消费 ChatGPT Plus/Pro 订阅配额
   - Codex CLI 自身使用同一 OAuth 机制

3. **`anthropics/claude-code` repo 不是 CLI 源码**
   - 该 repo 仅含文档 / examples / plugins / installer
   - 真正的 Claude Code CLI 是**闭源商业产品**
   - 2026-03-31 源码泄露事件：Anthropic 在 `@anthropic-ai/claude-code` npm 包里意外带 sourcemap，TS 源码被社区 mirror 到多个 GitHub repo（`yasasbanukaofficial/claude-code` v2.1.88、`liz-in-tech/open-claude-code` 等）

4. **Claude Code 与 Codex CLI harness 几乎对等**
   - 两家都支持：subagents、skills、slash commands、permission modes、hooks、MCP、项目指令文件（`CLAUDE.md` vs `AGENTS.md`）
   - 差异主要在文件格式（`.claude/agents/*.md` frontmatter vs `.codex/agents/*.toml`）和 permission 粒度（Claude 6 档 vs Codex 3 档）
   - SKILL.md 格式**完全兼容**（`name` + `description` 必需字段相同，directory 布局相同）

5. **Harness 和模型是耦合的**
   - Claude Code 的 system prompt 和工具 schema 为 Claude 模型深度优化
   - Codex CLI 的 harness 为 GPT-5.x 家族优化
   - 跨 harness 跑模型（Codex 模型在 Claude harness 上）存在翻译层损失，benchmark 数据显示原生组合性能最优

## 方案 A（存档备用）：Fork leaked Claude Code + 内嵌多 provider

### 核心设计

- Fork `yasasbanukaofficial/claude-code`（或同类 mirror）的 v2.1.88 TS 源码
- 保留 AnthropicProvider **字节级不变**，规避 Anthropic 服务端指纹识别
- 新增 Codex OAuth 登录子命令 + CodexProvider（调 OpenAI Responses API）
- 从 `raine/claude-code-proxy` 移植 TS 格式翻译层（Anthropic Messages ↔ OpenAI Responses API）
- `/model <model-id>` 根据前缀路由 Provider，会话内热切

### 吸引力

- **同 session 秒切 provider**：`/model claude-sonnet-4.5` → `/model gpt-5-codex` 对话连续
- Claude 订阅 + Codex 订阅同时可用
- 100% 保留 Claude Code 原生 harness

### 致命缺陷

1. **法律风险**：基于 leaked 源码，Anthropic 可随时 DMCA takedown；private repo 降低曝光但未根除
2. **版本冻结**：v2.1.88 快照跟最新 v2.1.119 差 31 版本，3 周迭代差距无法补上（Anthropic 早已修复 sourcemap 泄露）
3. **Anthropic attestation 风险**：服务端目前靠请求指纹识别；未来加 binary attestation / OS-level attestation 时 fork 无解
4. **维护负担**：没有上游可 rebase，每次 Anthropic 新 feature 都要反编译 bundled JS 手工移植
5. **Harness-model 耦合次优**：Codex 模型跑在 Claude Code harness 上，性能不如原生 Codex CLI

### 保留条件

方案 A 的 `docs/plans/2026-04-24-claude-code-multi-auth.md` 设计蓝图已完整保留。**未来以下任一条件触发时重新考虑**：

- 方案 F 的"跨 CLI resume 摘要"损失变得不可接受（比如需要高频切换 + 完整 tool 历史保真）
- OpenAI / Anthropic 改变订阅接入政策，双 CLI 并存不可行
- fork 的法律 / 技术风险缓解到可接受水平（比如 Anthropic 官方开源或授权 fork）

## 方案 F（当前采用）：双官方 CLI + `continues` session bridge

### 核心设计

- **Claude 通路**：官方 `claude` CLI，走 Claude 订阅，harness 原生最优
- **Codex 通路**：官方 `codex` CLI，走 ChatGPT 订阅，harness 原生最优
- **跨 CLI 会话延续**：`continues` 工具（`npm install -g continues`）读源 CLI 的 session 存储（JSONL / SQLite / ...），提取 messages + tool activity + thinking blocks + subagent dispatches，注入目标 CLI 作为 handoff prompt
- **Skill 共享**：`~/.codex/skills/<name>` 用 NTFS junction 指向 `~/.claude/skills/<name>`，Claude 的 16 个全局 skill 被 Codex 自动识别
- **跨 CLI 文件**：项目级两份（`.claude/agents/` + `.codex/agents/`、`CLAUDE.md` + `AGENTS.md`），可写 converter 同步；全局 skill 已统一

### 工具链

| 组件 | 版本 | 角色 |
|---|---|---|
| `claude` CLI | 官方 npm `@anthropic-ai/claude-code@latest` | Claude 订阅 |
| `codex` CLI | 官方 npm `@openai/codex@0.124.0` | ChatGPT 订阅 |
| `continues` | npm v4.0.12 | 跨 CLI session bridge |
| NTFS Junction | Windows 内置 | 共享全局 skill |

### 优缺对比方案 A

| 维度 | A（fork） | F（双 CLI + bridge） |
|---|---|---|
| 同 session 秒切 provider | ✅ | ❌ 切 CLI 进程（几十秒） |
| 跨 CLI 会话延续 | ✅（同一 CLI 内透明） | ✅（`continues resume`） |
| Harness-模型原生匹配 | ❌（Codex 跑 Claude harness） | ✅ 各自最优 |
| 合法性 | ❌ 灰色（leaked 源码） | ✅ 完全合法 |
| 工作量 | 中-大（几周） | **10 分钟** |
| 长期维护 | ❌ 冻结 v2.1.88 | ✅ 两家官方跟随 |
| Anthropic attestation 风险 | ⚠️ 中高 | ✅ 零（用官方 binary） |
| Opus 4.7 / GPT-5.5 等新模型 | 需 patch 硬编码 | ✅ 官方 CLI 自动跟进 |

F 方案的唯一代价是**不能同 session 秒切 provider**——实测真实使用里极少需要此能力（多数场景是"切 CLI 换思路"有意动作），可接受。

### F 方案落地记录（2026-04-24）

1. **装 `continues` v4.0.12**
   ```bash
   npm install -g continues
   continues scan   # 验证扫到 180 Claude sessions + 93 Codex sessions
   ```

2. **Skill junction 建立**（Windows NTFS Junction，不需要管理员权限）
   ```powershell
   $claudeSkills = "$env:USERPROFILE\.claude\skills"
   $codexSkills = "$env:USERPROFILE\.codex\skills"
   Get-ChildItem -Path $claudeSkills -Directory | ForEach-Object {
       $target = Join-Path $codexSkills $_.Name
       if (-not (Test-Path $target)) {
           New-Item -ItemType Junction -Path $target -Target $_.FullName
       }
   }
   ```
   16 条 junction 建立：cleanup / dev / evolvable-coding / first-principles-thinking / fix / frontend-design / implementation-discipline / log-fix / pipeline / plan / resume / review / self-improving-agent-3.0.0 / session-discipline / ship / solution-standards。Codex 的内置 `~/.codex/skills/.system/` 保留未动。

3. **SKILL.md frontmatter 补丁**：`cleanup` / `dev` / `review` / `ship` 四个 skill 原本没有 YAML frontmatter（Claude Code 容忍，Codex CLI 严格要求 `name` + `description`）。已在每个文件顶部补上 `---` 包裹的 frontmatter，对 Claude 完全向后兼容。

4. **`~/.codex/config.toml` 清理**：删除 `[mcp_servers.linear]` 段（未登录且不用），避免每次启动 warning。

5. **Codex CLI 更新**：`npm update -g @openai/codex` → 0.124.0（npm registry 当时最新）；启动验证 gpt-5.5 high 模型可用，16 skill 全部加载无报错。

### 维护规则

新增全局 Claude skill 时，补一条 junction：

```powershell
New-Item -ItemType Junction `
  -Path "$env:USERPROFILE\.codex\skills\<new-name>" `
  -Target "$env:USERPROFILE\.claude\skills\<new-name>"
```

或重跑落地步骤 2 的 PowerShell 脚本（`-not (Test-Path)` 会 skip 已存在项，只加新的）。

### 典型使用流

```bash
# Claude 订阅做事：复杂前端、架构决策、refactor
claude
> 让它做事，退出时 /exit

# 切 Codex 订阅继续做：terminal 脚本、DevOps、快速自动化
continues codex   # 带上 Claude 侧 session 摘要 + tool 活动

# 或反向：从 Codex session 切到 Claude 继续
continues claude
```

## 未来评估

每 3-6 个月重新审视以下问题：

- Anthropic 是否加了 binary attestation（会影响方案 A 未来可行性）
- OpenAI 是否改变第三方 OAuth 政策
- `continues` / 类似 bridge 工具的保真度提升（若能无损传递 tool history，F 方案体验进一步缩小与 A 差距）
- 本项目 ResearchAgent 是否出现"需要同 session 秒切 provider"的强需求（极少见，若出现再回到方案 A）

维持当前选择的条件：**F 方案没暴露不可接受缺陷 + 双 CLI 并存工作流能满足 95%+ 场景**。
