# v3.0 — MambaResearch 蜕变为 Claude Code / Codex 上层壳

**发布日期**: 2026-04-26
**主线**: 架构枢转，删除自建 multi-agent runtime；产品定位改为"Claude / Codex 之上的研究向可视化 IDE"

## 一句话定位

> MambaResearch v3.0 = Claude Code / Codex CLI 之上的研究向 IDE，零 LLM 路由、零 agent
> runtime、零自建 skill 注册表。所有"agent 智能"由订阅的 CLI 提供；所有"自定义能力"
> 通过 MCP server 接入；所有"研究流程结晶"沉淀在 sub-agent + pipeline SKILL.md。

## 为何枢转

v2.x 系列里 MambaResearch 仍持有一个独立的 `dynamic_os` 子系统（21 builtin skill +
7 role + planner + executor + policy engine + tool gateway，约 10k+ LOC），它做的事
情和 Claude Code / Codex 原生提供的"sub-agent + Task tool + MCP servers + 权限提示
+ 会话存储"高度同构。Stage 5 实施期间多次撞上以下问题：

- 同样的 LLM 调用要在两边各跑一份（dynamic_os ConfiguredLLMClient + Claude/Codex
  内部 LLM），账号 / token / 限速重复消耗
- 21 个 builtin skill 的 prompt 工程精华、7 个 role 的分工，已经天然适合直接表达为
  Claude / Codex 原生 sub-agent 的 system prompt
- "DAG 编排"在 Claude / Codex 主 agent 的 plan-and-execute 模型下属于冗余抽象
- 自建 artifact / hitl / memory 子系统都各自有原生对应物可用

第五次纠偏在 Stage 5 v2 (DAG-as-MCP) 落地前触发。结论：**完整删除 dynamic_os**，
把它的设计精华平移到 Claude / Codex 原生扩展点。

## v3 三层架构

```
MambaResearch UI（薄壳）
        │
        ▼
Claude Code / Codex CLI（引擎，唯一 LLM 出口）
        │
        ▼
MCP Servers（统一扩展机制）
```

UI 拥有 6 个可视化域：

1. Claude Code 可视化：工作台 / 技能 / Agent 角色 / 历史 tab
2. 文件管理可视化：4 bucket（实验 / 文献 / 数据集 / 灵感）
3. MCP 功能可视化：servers / tools / 调用历史 / sandbox 试调 / 配置编辑
4. 实验执行可视化：情境性 tab，跑 `experiment.*` MCP 看 metric 流
5. 文献阅读可视化：情境性 tab，PDF 嵌入 + 摘要 + 标注
6. Agent 思考可视化：情境性 tab，thinking blocks + tool call timeline

## v3 新增 / 沉淀清单

### 8 个 sub-agent（`.claude/agents/*.md` + `.codex/agents/*.toml`）

| Sub-agent | 来源 dynamic_os skill | 模型档位 |
|---|---|---|
| paper-searcher | search_papers + fetch_fulltext | haiku |
| evidence-extractor | extract_notes + build_evidence_map | haiku |
| analyzer | analyze_metrics / analyze_trends / aggregate_results / compare_methods / generate_figures / reflect_on_failure / optimize_experiment | sonnet |
| writer | draft_report | sonnet |
| critic | review_artifact (重度) | opus |
| **conductor** (新) | clarify_intent + plan_research | sonnet |
| **experimenter** (新) | design_experiment + run_experiment + optimize_skill + create_skill | sonnet |
| **reviewer** (新) | review_artifact (流程内审，5 维评分) | sonnet |

`.claude/agents/*.md` 是真相源；`scripts/sync_subagents.py` 一键同步成 `.codex/agents/*.toml`。

### 7 个 pipeline SKILL.md（`.claude/skills/`）

| Pipeline | 主 sub-agent 链 |
|---|---|
| structured-lit-review | paper-searcher → evidence-extractor → analyzer → writer → critic |
| empirical-study | conductor → experimenter (× N iter) → analyzer → writer |
| method-comparison | paper-searcher → evidence-extractor → analyzer → writer |
| experiment-iteration | experimenter sweep → analyzer → reviewer |
| artifact-review | reviewer (5 维) → critic (🔴/🟠/🟡) |
| idea-brainstorming | conductor → analyzer → critic |
| data-exploration | conductor → analyzer → writer |

每个 SKILL.md 含 5 段：何时调用 / 步骤列表（spawn 哪个 sub-agent + 写哪个文件）/
artifact 命名约定 / 失败策略 / 完成态。

### Workspace artifact 命名约定

所有 sub-agent 通过 `outputs/<run_id>/` 下的标准文件互通，不再依赖 in-memory artifact
store。`run_id` 格式按 pipeline 类型约定（如 `lit_review_<YYYYMMDD>_<HHMMSS>`）。
完整约定写入 `CLAUDE.md` + `AGENTS.md` 双侧暴露。

## 不再做的事

- 不自建 LLM routing（v2.0 起 `role_models` 已废，v3 永远不复活）
- 不自建 multi-agent runtime / DAG executor / skill registry / sub-agent registry
- 不自建 session 存储 / message log（用 CLI JSONL；跨 CLI 桥用 `continues`）
- 不自建 auto-compact 主路径（用各 CLI 原生；MambaResearch 仅做 token-usage 监听 + 兜底）
- 不自建 memory 基础设施核心（用 `<project>/.mambaresearch/memory/*.md` 共享文件 + `@import`）
- 不依赖 Claude-Code-only 的 user-level auto-memory（保持 backend 对等）
- 不做 multi-active workspace / multi-bucket primary 归属 / 物理文件移动 / Drive API
  直接集成 / Colab 远程执行 / Zotero 7 localhost API / Pipeline 模板调度系统 /
  multi-tenant 权限系统
