# v0.9 - 6-Agent Research Operating System

> **Commit**: `41f3635` · **日期**: 2026-03-09 · **Tag**: `v0.9-research-os-6agent`

## 版本定位

首次覆盖**完整科研链路**的 6 角色协作版本，**"Research Operating System"** 概念正式定型。从 v0.5 的 3 角色扩展为 6 角色后，配套前后端集成也同步落地（`41f3635 feat: Complete frontend-backend integration for 6-agent display`）。

此版本仍跑在 LangGraph 状态图之上——它是"角色 + skill"概念层的完整版，但还没摆脱底层框架依赖。

## 主要能力

- **6 角色协作**：conductor / researcher / experimenter / analyst / writer / reviewer
- **完整 skill wrapper 系统**：每个角色的职责被拆成独立 skill，统一走 wrapper 接入（`5cd1ac4 Implement complete 6-agent skill wrappers`）
- **orchestrator 集成**：6 角色调度走统一 orchestrator，不再和 LangGraph 节点逻辑混杂（`5126b7f Complete 6-agent orchestrator integration`）
- **前后端 6-agent display**：UI 首次能按角色可视化运行状态
- **Research OS phase 规划**：`docs/` 首次有系统化的 Research OS 分阶段规划文档

## 技术栈

- **编排**：LangGraph + 6-agent orchestrator 双层
- **角色系统**：`src/agent/roles/` 首次把角色抽象成一等对象
- **前端**：按角色分面板展示执行状态

## 当时的局限

- **LangGraph 仍是底层依赖**——6 角色是包装层，运行时底座没换
- 角色之间的数据流还靠状态字典，没有强类型 artifact 契约
- 调度是静态的（固定 DAG），LLM 不参与"下一步做什么"的决策
- 技能不能动态增删，所有行为硬编码

## 为什么进化到下一版

6 角色架构概念完整了，但**引擎还是 LangGraph 的**——无法做动态 DAG 规划、无法强类型约束 artifact、无法动态 evolve 技能。3 天后（2026-03-12）**v1.0 Dynamic OS** 自建 runtime 上线，同天 `648a12d` 清除 legacy agent 实现，LangGraph 正式告别。
